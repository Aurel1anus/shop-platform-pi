原项目的 Agent 功能

用户输入
│
├─ “预算 300，推荐敏感肌能用的面霜”
│       └─ 搜索商品 + 查询知识 → 推荐理由 + 商品卡片
│
├─ “前两个有什么区别？”
│       └─ 结合历史商品顺序 → 比较与选购建议
│
├─ 上传图片：“帮我找类似的”
│       └─ 图片向量检索 → 相似商品
│
├─ “把第二个加入购物车”
│       └─ 解析历史指代 → 实际加购 → 购物车结果
│
├─ “有哪些优惠？帮我领取”
│       └─ 查询促销/优惠券 → 领取或优惠试算
│
└─ “下单 / 查订单 / 支付 / 确认收货”
        └─ 调用业务工具 → 更新订单并返回实际结果

支付是本地虚拟支付；售后主要提供说明和入口，尚未实现完整退款流程。语音输入和回复朗读也有实现，依赖外部语音服务配置。

原 Agent 的内部架构

它主要是一个自研 Agent 循环，前面加了记忆和意图分类。

Android 客户端
      │ 文字 / 图片 / 语音识别后的文字
      v
Go HTTP API
      │ 鉴权、消息去重、创建运行记录
      v
+--------------------------------------------------+
|                 Agent Runtime                    |
|                                                  |
|  风控检查                                        |
|      │                                           |
|      v                                           |
|  会话记忆：历史需求、推荐商品、指代关系             |
|      │                                           |

|  +--------------------------------------------+  |
|  | 模型决策                                   |  |
|  |    │                                       |  |

|  |    ^                                   │  |  |
|  |    └───────────────────────────────────┘  |  |

|  |    └── 信息足够 ──> 最终回答                |  |

      │
      v
SSE 流式输出
      ├─ 回答文字
      ├─ 商品、购物车、订单卡片
      └─ 后续问题建议

运行过程中保存 trace，供管理员排查模型和工具调用。

原循环最多执行 6 个决策步骤。工具调用和最终输出采用自定义 JSON、<final> 等协议，并校验商品引用，限制模型编造商品。

抽离出的 shop-platform 后端

按你要求接入 pi 后的目标架构

下面是业务完整接入的目标：pi SDK、插件加载和状态工具已接通，HTTP、业务工具、记忆和 RAG 尚未实现：

用户 / 客户端
      │
      v
Agent 请求入口
      │
      v
+------------------ Harness -----------------------+
| 身份上下文、会话历史、商品指代、工具权限           |
| 请求去重、超时、取消、调用预算、消息与 trace 保存  |
|                                                  |
|              +------ pi Loop ------+             |
|              | 模型决定下一步      |             |
|              |        │            |             |
|              |        v            |             |
|              | 调用工具，读取结果  |             |
|              |        │            |             |
|              | 继续或结束回答      |             |
|              +--------+------------+             |
+-----------------------|--------------------------+
                        │
             +----------+----------+
             │                     │
             v                     v
       自写 RAG                业务工具适配器
       召回、重排                  │ HTTP
             │                     v
             v               Go 业务后端
       原文 / 检索索引             │
                              +----+----+
                              │         │
                            MySQL     MinIO

核心边界是：pi 负责模型循环，harness 负责执行管理，RAG 提供检索依据，Go 后端负责真实业务操作。 当前新后端可以独立运行，聊天、语义检索和旧 AI 管理接口暂时返回 501，等待新 Agent 接入。
